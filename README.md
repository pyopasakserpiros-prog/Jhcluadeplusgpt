# สำนักเมฆาหยก — Jianghu Sect

เกมจำลองสำนักยุทธภพแบบออฟไลน์: ซอร์สล่าสุดอยู่ใน [`JianghuSect_v1.10/`](JianghuSect_v1.10/) และไฟล์เล่นแบบเดียวอยู่ที่ [`JianghuSect_single.html`](JianghuSect_v1.10/JianghuSect_single.html) เปิดด้วยเบราว์เซอร์และเริ่มเกมใหม่ เวอร์ชันใหม่นี้ไม่ได้รับประกันความเข้ากันได้กับเซฟเก่า

## สิ่งที่เพิ่มล่าสุด

- **ระบบบันทึกเหตุการณ์สำนักยุทธภพและตัวกรองหลายหมวดหมู่ (Rich Event Log & Multi-Category Filtering)**:
  - **บันทึกจากเหตุการณ์ที่เกิดขึ้นจริง (Truthful Event Logging)**: รายงานเหตุการณ์จริงครบทุกมิติ ได้แก่ การบาดเจ็บ การรักษาพยาบาล การฟื้นตัว การเสียชีวิต, การเผชิญหน้า ล่า ชนะ ล่าถอยจากสัตว์อสูร, การปรากฏตัวและจากไปของอสูรบรรพกาล/ตำนาน, การเก็บสมุนไพร ชำแหละอสูร และบริจาควัตถุดิบ, การปรุงโอสถสำเร็จ/ระดับบริสุทธิ์เลิศล้ำ/ล้มเหลว, การใช้โอสถส่วนตัวและสวัสดิการ, การซื้อขายภายนอก และการตัดสินใจแต่งตั้ง/ขยายอาคาร/ชะลอเพราะขาดทรัพยากร
  - **สำนวนภาษาไทยธีมยุทธภพหลากหลาย (Varied Thai Wuxia Phrasing)**: มีข้อความสลับเปลี่ยนตามบริบทโดยใช้การคำนวณเชิงตัวเลขกำหนดตัวเลือกแบบ deterministic โดยไม่รบกวนลำดับ `W.rng` ของเกม
  - **แถบตัวกรองหลายหมวดหมู่แบบ Multi-Select**: รองรับการเลือกดูหมวดหมู่ต่าง ๆ พร้อมกันหรือดูทั้งหมด (`ทั้งหมด`, `👥 ผู้คน`, `⚔️ ต่อสู้/ล่า`, `⚗️ การผลิต`, `🪙 เศรษฐกิจ`, `🏯 อาคาร`, `⭐ สำคัญ`) พร้อมปุ่มชิปสัมผัสขนาดใหญ่เหมาะสำหรับอุปกรณ์มือถือ
  - **จำกัดปริมาณบันทึกในหน่วยความจำ**: จัดการประวัติด้วย Ring buffer ป้องกันหน่วยความจำบวมบนอุปกรณ์มือถือ

- **พื้นที่อสูรรอบกำแพงสำนัก 4 ทิศ และระบบหลาย Pool ต่อโซน (4-Direction Outer Wildlife & Multi-Pools)**:
  - **ขยายพื้นที่รอบกำแพง 4 ทิศ**: เพิ่มพื้นที่เดินได้รอบกำแพงด้านประจิม (ตะวันตก - ป่าไผ่หมอกคราม), บูรพา (ตะวันออก - หน้าผาหินแกร่ง), อุดร (ทางเหนือ - ยอดเขาเหมันต์) นอกเหนือจากทักษิณเดิม (ทางใต้ - ทุ่งหญ้าและแนวผา)
  - **ประตูและเส้นทางสัญจร 4 ทิศ**: เจาะประตูกำแพงและสร้างถนนเชื่อมต่อทั้ง 4 ทิศ (ประตูประจิม $x=30, y=80$, ประตูบูรพา $x=210, y=80$, ประตูอุดร $x=118, y=18$, ประตูทักษิณ $x=118, y=132$) ให้สมาชิกเดินเข้า-ออกสำนักและนำทางด้วย A* ได้อย่างไร้รอยต่อ
  - **ระบบหลาย Pool ต่อโซน (Multi-Pool per Zone)**: แต่ละโซนมี Pool ย่อยอย่างน้อย 2–3 Pool ที่มีช่วงระดับพลัง (tier band) สอดคล้องกับโซน เช่น โซนประจิม (ขั้น 2–4), โซนบูรพา (ขั้น 3–5), โซนอุดร (ขั้น 4–6 และอสูรตำนาน), และโซนทักษิณ (ขั้น 1–7)
  - **กฎระเบียบและประสิทธิภาพ**: อสูรไม่บุกเข้ากำแพงสำนัก, อสูรระดับต่ำใกล้สำนักไม่ก้าวร้าวก่อน, การต่อสู้ถูกตรึงพิกัด (clamp) ให้อยู่นอกกำแพงเสมอ, อสูรตำนานไม่หายไปกลางศึก, วัตถุดิบและอวัยวะที่ล่าได้ไหลเข้ากระเป๋าส่วนตัวของสมาชิก (`n.inv.mats`, `n.inv.organs`) เพื่อนำไปปรุงโอสถหรือบริจาคแลกแต้มคุณูปการเข้าคลังสำนัก, พร้อมจำกัดจำนวนอสูรพร้อมกันไม่เกิน 10–12 ตัวเพื่อประสิทธิภาพบนมือถือ

- **แก้บั๊กความต้องการสถานีที่เคยเต็มแล้วค้างอยู่ (Facility Congestion Demand Decay)**:
  - **ระบบเสื่อมค่าตามเวลา (Time-Weighted Demand Decay)**: เพิ่ม `SECT.decayFacilityDemand` ในรอบวัน (`SECT.daily`) หากสถานีไม่มีความแออัดค้างเกิน 2 วัน ค่าความต้องการ (`failedAttempts`, `unmetDemands`, `congestedHours`) จะถูกล้างเป็น 0 ทันที หากเกิน 1 วันจะลดลงครึ่งหนึ่ง
  - **การขยายอาคารตามความต้องการจริงต่อเนื่อง**: ตรวจสอบความสดใหม่ของสัญญาณความต้องการ (`effFailed`, `effCongested`) ป้องกันการสั่งขยายอาคารจากเหตุการณ์เต็มเพียงครั้งเดียว (isolated spike) หรือจากสัญญาณค้างในอดีต โดยต้องมีความแออัดต่อเนื่องจริง ($\ge 2$ ครั้ง หรือ $\ge 3$ ชม.)
  - **ป้องกันคำสั่งซ้ำซ้อน**: ชะลอการสั่งก่อสร้างเพิ่มหากมีอาคารใดกำลังก่อสร้างอยู่ (`underConstruction`) และรีเซ็ตค่า demand ทันทีที่เริ่มการก่อสร้าง

- **ระบบปัญญาประดิษฐ์เศรษฐกิจและขยายสิ่งก่อสร้างตามอุปสงค์ (Autonomous Economy & Demand-Driven Facility Expansion)**:
  - **ปัญญาประดิษฐ์ประเมินคลัง (Inventory Intelligence)**: ติดตามอัตราการเบิกจ่ายจริงย้อนหลัง 14/30 วัน จัดหมวดหมู่ 4 ระดับ (`shortage`, `reserve-required`, `balanced`, `surplus`) พร้อม hysteresis ป้องกันการแกว่งและระบบแคชรายวัน
  - **การค้าภายนอกอัตโนมัติ (Autonomous Trade)**: ขยายการซื้อขายกับพ่อค้าภายนอก (`EXT.tradeSect`) ขายเฉพาะส่วนเกินคลังจริงโดยไม่กระทบสต็อกสวัสดิการ ฉุกเฉิน หรือการผลิต พร้อมระบบจัดซื้อของขาดแคลนอัตโนมัติตามคำสั่งคลัง และรักษากันชนเงินสดสำนักขั้นต่ำ (`cashReserve`)
  - **ระบบป้องกันอาร์บิทราจและติดตามแต้มคุณูปการ (CP Circulation & Anti-Arbitrage)**: สกัดลูปซื้อวัตถุดิบมาผลิตบริจาควนซ้ำ โดยจำกัดแต้มรับบริจาคที่ผลิตจากวัตถุดิบร้านค้าสำนักไม่เกิน 88% ของต้นทุนซื้อ พร้อมติดตามแต้มที่หมุนเวียนจริง (`circulation`), แต้มที่ปลดเกษียณเมื่อสมาชิกเสียชีวิตหรือพ้นสำนัก (`retired`), และสถิติสกัดอาร์บิทราจ (`arbitrageBlocked`)
  - **ความโปร่งใสของผู้เล่น**: แสดงป้ายสถานะคลัง (ส่วนเกิน/ขาดแคลน/สำรอง), แผงติดตามแต้มหมุนเวียนในร้านค้า, และสถานะความแออัดของสิ่งก่อสร้างใน UI สำนัก พร้อมบันทึกเหตุผลการตัดสินใจทุกรายการลง Log
- เขตล่าอสูรอยู่นอกกำแพงบนแผนที่เดียวกัน แยกจากคณะเดินทางนอกสำนัก มีเขตระดับต่ำและเขตอันตราย ใช้ข้อมูลอสูรและวัตถุดิบเดิม สมาชิกตัดสินใจล่า ต่อสู้ และเก็บของที่ได้จริง
- อสูรระดับต่ำใกล้สำนักไม่โจมตีก่อน บางชนิดในเขตอันตรายโจมตีเมื่อเข้าใกล้ อสูรในตำนานเกิดยาก อยู่ 3–10 วันแบบสุ่ม และไม่หายกลางการต่อสู้
- สมาชิกที่รู้สูตรสามารถใช้วัตถุดิบส่วนตัวปรุงโอสถที่เตา ซื้อของที่ขาดจากคลังด้วยแต้มเมื่อมีของและแต้มพอ และเก็บหรือบริจาคโอสถที่ผลิตจริง คุณภาพส่งผลต่อการฟื้นฟูและแต้มบริจาค การซื้อของมาผลิตบริจาคมีเพดานป้องกันแต้มเพิ่มจากการวนซื้อเพียงอย่างเดียว; เมื่อของล้นคลังมาก รางวัลบริจาคลดลงต่อเนื่องตามอุปทาน
- การแจกโอสถใช้ของจริงในคลัง ผู้ดูแลคลังหรือเจ้าสำนักแจกตามนโยบาย ความจำเป็น และความสัมพันธ์ มีการเลือกผู้รักษาการเมื่อผู้รับผิดชอบไม่พร้อม พร้อมบันทึกการมอบและผู้ทำหน้าที่
- ก่อนหน้านี้ปรับกราฟฟิกสำนัก เอฟเฟกต์ร่วมของวิชาปกติ/ต้องห้าม และถ้ำ 10 ชั้นที่สุ่มพื้นที่ย่อย/เหตุการณ์จากแต่ละ pool

## ขอบเขตและประเด็นต่อยอด

- การซื้อวัตถุดิบที่ขาดเกิดระหว่างการผลิตส่วนตัว ยังไม่มีหน้าร้านวัตถุดิบแยกให้เลือกซื้อเอง และการผลิตส่วนตัวรอบนี้รองรับโอสถเป็นหลัก
- คุณภาพโอสถในคลังรวมเป็นค่าเฉลี่ยตามชนิด ไม่ได้แยกล็อตคุณภาพทุกชุด
- การจำลอง 360 วัน seed `economy-long` หลังจูนล่าสุดมีแต้มจ่ายออก 59,717 ใช้คืน 40,258 สมาชิก 56 คน การซื้อ 708 ครั้ง และดัชนีราคา 0.99; ยังต้องติดตามหลาย seed และหลายปี ไม่ควรสรุปว่าเศรษฐกิจสมดุลถาวร
- การตัดสินใจขยายอาคารเดิมยังไม่ได้ประเมินการใช้สถานีเต็มโดยตรง; อัปเกรดเพิ่มสถานีได้ แต่ระบบคอขวดความต้องการเป็นงานต่อยอด

  - สร้างไฟล์เล่นเดี่ยว [`JianghuSect_single.html`](JianghuSect_v1.10/JianghuSect_single.html) ล่าสุดขนาด 1,293 KB เรียบร้อยแล้ว พร้อมเล่นได้ทันทีแบบออฟไลน์

## สำหรับผู้พัฒนาและ AI ที่มารับช่วง

อย่าแก้ `js/human_core.js` โดยไม่มีความจำเป็น: โครงการมีข้อกำหนดตรวจ byte lock ไฟล์นี้ ก่อนแก้ระบบให้ตรวจ source และ test ที่เกี่ยวข้องก่อน; หลีกเลี่ยงการใช้ผลทดสอบเก่าที่ติดอยู่ใน ZIP มาแทนผลรันใหม่ ไฟล์ `SOURCE_REFERENCE/` เก็บต้นฉบับเพื่ออ้างอิง ไม่ใช่ runtime หลัก

- แผนที่และทางเดิน: `js/world_map.js`; อสูรบนแผนที่และการล่า: `js/wildlife.js`; ต่อสู้: `js/combat.js`; กราฟฟิก: `js/render.js`
- ผลิต/วัตถุดิบ: `js/economy.js`; แต้ม ร้าน สวัสดิการ และกิจกรรมผลิตส่วนตัว: `js/cpeco.js`; นโยบาย/เจ้าสำนัก: `js/sect.js`
- เริ่มเกม/serialize: `js/sim.js`; script loading: `index.html` และ `test/load.js`; สร้างไฟล์เล่นเดี่ยว: `tools/build_single.js`
- ถ้ำและ pool: `js/explore.js`; ระบบพื้นที่นอกสำนักแบบคณะเดินทาง: `js/content.js` และ `js/expedition.js`

จากโฟลเดอร์ `JianghuSect_v1.10` ใช้ `node tools/build_single.js` หลังแก้ runtime; `node test/run_all.js` รันชุดทดสอบรวม โดย browser tests ต้องมี Playwright และ Chromium ที่ใช้งานได้ และต้องอนุญาต process/socket ในสภาพแวดล้อมนั้น ใช้ `node test/long_simulation.js <seed> <days> <output.json>` ตรวจผลจำลอง; ใช้ `python3 tools/package_release.py <output.zip>` สร้าง ZIP พร้อมตรวจไฟล์และ CRC

การทดสอบในคลาวด์รอบนี้ใช้ HTTP ภายในและ Chromium ของระบบ เพราะนโยบายเครื่องบล็อก `file://` โดยตรง และ browser performance เป็นเกณฑ์ขึ้นกับทรัพยากรเครื่อง จึงไม่ใช่การรับรองบนมือถือจริง รายละเอียดกราฟฟิกและถ้ำอยู่ใน [`docs/GRAPHICS_UPDATE_TH.md`](JianghuSect_v1.10/docs/GRAPHICS_UPDATE_TH.md) และ [`docs/CAVE_UPDATE_TH.md`](JianghuSect_v1.10/docs/CAVE_UPDATE_TH.md)
