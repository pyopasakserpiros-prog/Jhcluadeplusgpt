# ประเด็นพัฒนาต่อหลังตรวจแพทรวม Gemini

สถานะ: ประเด็นจากการอ่านโค้ด/ทดสอบ ไม่ใช่รายการที่แก้ครบแล้ว และยังไม่กำหนดแพท

1. **ผู้พิทักษ์ยังเป็นการตัดสินแบบย่อ** — VC.evaluateClueNode ใช้ partyPower เทียบ guardianPower สุ่มผลและหัก HP โดยคงไว้อย่างน้อย 1 ไม่ได้สร้างศัตรูและเล่น combat encounter เต็มรูปแบบ ต้องเลือกว่าใช้ abstraction เดียวกับคณะเดินทางให้สอดคล้อง หรือเพิ่มศึกจริง รวมการถอย/บาดเจ็บ/ต้นทุน/ผลตายที่สมเหตุสมผล ห้ามบอกผู้เล่นว่าได้ดูศึกจริงหากเป็นการคำนวณย่อ
2. **เรื่องเล่ามากกว่ากลไกที่หลากหลาย** — ขั้นหลายชื่อยังจบด้วยค่า skill/stat + สุ่ม บททดสอบจิตใจ/การพูดคุยยังไม่เท่ากับการตัดสินจากพฤติกรรมจริง ควรเพิ่มคำมั่นที่ทำสำเร็จ การเลือกที่มีต้นทุน ทางเลือกหลายแบบ และผู้ติดต่อที่มีตัวตน โดยไม่ขยายทุกเรื่องให้ยาวเท่ากัน
3. **เส้น A -> B ข้ามสถานที่ยังไม่ใช่จุดเด่นจริง** — พบเส้นภายนอกที่ต่อกันมักใช้ภูมิภาคเดียวกัน ตรวจระบบ travel/known nodes ก่อนเพิ่มเส้นข้ามภูมิภาค ให้ความรู้ของแต่ละคนพัฒนาเฉพาะสิ่งที่ทราบ ไม่ตามอ่าน currentNodeIdx และค่า requirement ลับทั้งโลก
4. **ผู้ร่วมเดินทางยังใช้ความยินยอมแบบหยาบ** — แม้แก้ protected action แล้ว เงื่อนไขความสัมพันธ์ >= -5 กับ energy ยังไม่ใช่การตอบรับคำเชิญตามเป้าหมาย/หน้าที่/ความเสี่ยง ควรเชื่อม commitment และ party consent จากแพท NPC อย่างเต็มที่ รวมผู้อนุมัติเสบียง/เงินสำนักตามอำนาจจริง
5. **ข่าวตำนานอาจมากเกินเมื่อเนื้อหาทั่วไปมีน้อย** — pool มีทั่วไป 8 ต่อเป้าหมายตำนาน 33 จำนวนผู้สมัครใน pool กับ cooldown ส่งผลต่ออัตรารวม ต้องวัด conditional/per-day/grants/learned แยกกัน ก่อนปรับ อย่าอ่านน้ำหนักต่อชิ้นแล้วสรุปว่าข่าวตำนานหายาก เพิ่มข่าวทั่วไปและข่าวที่ไม่มีรางวัลตามตัวตนผู้มาเยือนได้
6. **การลองซ้ำและเก็บความทรงจำ** — บางรอบพบ node failures จำนวนมาก ควรมีการคาดการณ์ความพร้อม ระยะรอ เหตุผลฝึก/หาคนช่วย/ยอมเลิก และจำกัดประวัติราย instance โดยรักษา checkpoint สำคัญ ไม่ใช่แค่ cap จำนวน clues
7. **ประวัติคนและเจ้าของสมบัติ** — ตรวจการเก็บ offsite registry 48 รายกับ active references, links และความสัมพันธ์ที่อาจยังใช้งานอยู่ ตรวจ registry เจ้าของอาวุธหลังตาย ขาย โอน หรือเก็บคืน รวมสถานะของที่สูญหาย ไม่รับรองว่าเส้นทางที่ยังไม่ได้ทดสอบทำถูกแล้ว
8. **ความแม่นทางนิยายและสมดุลอาวุธ** — ตรวจแหล่งอ้างอิงแยก canon/ฉบับดัดแปลง/สร้างเอง และทดสอบ procs/ความเหมาะสมในศึกหลายรูปแบบ ไม่ควรให้คำว่า Legendary ชนะตัวเลือกอื่นเสมอ ความแรงแบบ same-tier และการซ้อนบัฟยังต้องเก็บข้อมูลเพิ่ม
9. **NPC อำนาจ/การรับรู้/ความฝันระยะยาว** — มีระบบเพิ่มจริงแต่ต้องตรวจผลเกิดตามธรรมชาติ ความคืบหน้าที่สัมพันธ์กับเป้าหมาย การรักษาการ ความลำเอียง/ยักยอก/การร้องเรียน และขอบเขตข้อมูลส่วนตัวอย่างเจาะจง ห้ามอ้างว่าผ่าน unit suite แล้วพฤติกรรมทั้งหมดเหมือนมนุษย์
10. **กราฟิกและประสิทธิภาพเครื่องจริง** — ภาพยังเป็น procedural และอาคารหลายอันยังใช้โครงร่วมกัน เพิ่มเอกลักษณ์โดยวัดต้นทุน ตรวจ overlay/อาวุธทุกชนิดบนเครื่องมือถือจริง รวม 100 สมาชิกพร้อมแขก/ฝน/ศึกและเซฟยาว

ใช้รายการนี้ร่วมกับ roadmap เดิม ผู้มาเยือน/อำนาจ/ความสัมพันธ์ และผลสังเกตจากการเล่นครั้งถัดไป ไม่ต้องเพิ่มทั้งหมดในแพทเดียว
