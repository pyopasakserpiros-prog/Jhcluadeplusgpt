# Jianghu v2.08.3 — แก้การถ่ายทอดตำรับและกู้คืนงานที่ค้าง

## บั๊กที่ยืนยันจากรายงานจริง
- รายงาน v2.08.2 หยุดที่ EP.8 / Tick 384 / เวลา 7692.4 ใน `LivingAcademy.finish()` ระหว่างจบ `shareFormula`
- สาเหตุที่ยืนยันจากโค้ด: ระบบเพิ่มสูตรเข้า `recipient.stageLocal.growth.knownRecipes` ก่อน จากนั้นเรียก `f.licenses.push(...)` แต่สูตรจากข้อมูลเก่าบางรายการไม่มี `licenses` array จึงเกิด `Cannot read properties of undefined (reading 'push')`
- การเรียงคำสั่งเดิมทำให้เกิด partial commit: สูตรถูกเพิ่มให้ผู้รับแล้ว แต่สิทธิ์ `USE_ONLY` ไม่ถูกบันทึก และงานค้างอยู่ในเซฟ

## การแก้ไข
- ย้ายการซ่อม schema เข้า `LivingAcademy` constructor เพื่อเติม `knownBy`, `licenses`, `history` และ `revision` ที่ขาดจากข้อมูลสูตรเก่า โดยไม่เปลี่ยน schema เซฟ v11
- ทำการจบงาน `shareFormula` ให้ idempotent: ไม่เพิ่มสูตรซ้ำ และเพิ่มใบอนุญาต `USE_ONLY` เฉพาะเมื่อยังไม่มี
- อนุญาตให้ ticket ที่ยินยอมและมี reservation/session ตรงกันกู้คืนการแชร์ที่ถูกบันทึกไปเพียงบางส่วน
- รายงาน runtime และไฟล์เซฟที่ส่งออกจากเกมใหม่ใช้ชื่อรุ่น v2.08.3
- คงแพตช์ EP.5 และความเร็ว ×1, ×2, ×4, ×8, ×16 ไว้

## การตรวจสอบ
- ทดสอบกับ `Jianghu_Runtime_Report_v2_08_2.json` จริง: โหลดเซฟเดิม, เรียก frame loop ต่อจากจุดหยุด, เวลาจำลองเดินต่อ, ticket ถูกปิด, ผู้รับมีสิทธิ์ `USE_ONLY`, และไม่มีสูตรซ้ำ
- ทดสอบ migration สูตรเก่าที่ขาด arrays ผ่าน
- ทดสอบความเร็ว ×1–×16 และการซ่อม needs ของเซฟเดิมผ่าน
- การทดสอบเต็มทั้งชุดต้องอ่านสถานะผลทดสอบฉบับสุดท้าย ไม่ถือว่าผ่านจนกว่าจะเสร็จครบ
