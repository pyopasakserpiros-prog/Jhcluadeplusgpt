## พฤติกรรมที่เปลี่ยน

`js/cognition.js` ต่อเข้ากับตัวเลือกกิจกรรมเดิม ไม่เรียก LLM ระหว่างเล่น ไม่ย้ายการจำลองไปอยู่ใน UI และไม่แก้ `js/human_core.js` ที่ล็อกไบต์ไว้

- มีความตั้งใจต่อเนื่อง: ฟื้นร่างกาย, เตรียมทะลวงขั้น, ออมแต้มเรียนวิชาที่สนใจ, เตรียมปรุงของส่วนตัว, ฝึกก้าวข้ามคู่แข่ง, ทำหน้าที่, ช่วยวิกฤตของขาด รวมถึงเลือกไม่มีเป้าหมายก็ได้
- เป้าหมายเพิ่มน้ำหนักให้กิจกรรมที่เกี่ยวข้อง ไม่ล็อกตัวละครไว้ในคำสั่งเดียว ความจำเป็นเร่งด่วนยังสำคัญกว่า เป้าหมายจบเมื่อสำเร็จ/เงื่อนไขใช้ไม่ได้/ขาดความคืบหน้าหรือหมดอายุสูงสุด 7 วัน
- ผู้มีเหตุผลสูงโน้มไปทางวิชาที่ได้ผล ส่วนผู้ให้คุณค่าความชอบสูงโน้มไปทางสายวิชาที่ถูกใจ ความอยากลอง อารมณ์ และวินัยปรับความแปรผันของการเลือก สมาชิกจึงยังเลือกต่างกันได้ในสถานการณ์คล้ายกัน
- ออมแต้มเรียนวิชาช่วยลดความอยากซื้อของ แต่ไม่ห้ามใช้เงินเด็ดขาด เมื่อเริ่มเรียนจะเลือกวิชาที่เล็งไว้หากเรียนได้และมีแต้มพอ แล้วหักแต้มจริงผ่านระบบเดิม
- จดผลล่าแพ้/ชนะเป็นข้อมูลมีชนิดและพื้นที่ ความพ่ายแพ้ลดความน่าล่าของพื้นที่นั้นตามความระวังและค่อย ๆ จางใน 14 วัน ไม่อ่านคำบรรยายมาทำนายเหตุการณ์
- จังหวะกลางวัน/กลางคืน ความเครียด ความเศร้า และความไม่สบายจากฝน/หิมะปรับความชอบกิจกรรม ไม่มีโบนัสสเตตัสตามสภาพอากาศที่เสกขึ้นใหม่
- คนที่มีความเห็นใจหรือความผูกพันพอ อาจเดินไปแบ่งโอสถฟื้นพลังชีวิตพื้นฐานที่ผู้รับใช้ได้จริง ย้ายหนึ่งเม็ดจากกระเป๋าผู้ให้พร้อมคุณภาพ ไม่เสกยา ไม่เพิ่มแต้ม และตรวจสถานะ/ระยะอีกครั้งเมื่อส่งมอบ

## ตำแหน่งและอำนาจ

อ่านบทบาทจาก `masterId` / `deputyId` / `sect.posts` ทุกครั้ง ไม่ให้อำนาจเจ้าสำนักเพราะมี rank สูงอย่างเดียว ผู้ช่วยรู้หน้าที่ฝ่าย แต่ไม่ออกใบสั่งผลิตหรือใช้สิทธิ์หัวหน้าฝ่ายเอง เจ้าหน้าที่ตาย/ออกเดินทาง/ถูกขัง/ปิดด่านไม่ออกข้อเสนอใหม่ ข้อเสนอเก่าใช้ไม่ได้เมื่อเจ้าของพ้นตำแหน่ง

| ตำแหน่ง | ข้อมูล/การตัดสินใจที่เชื่อมกับระบบ |
| --- | --- |
| เจ้าสำนัก | นโยบาย แต่งตั้ง สำรองทรัพยากร ขยายอาคาร วิจัย กิจกรรม และตรวจบัญชี; บุคลิกและของขาดปรับน้ำหนักการเลือก |
| รองเจ้าสำนัก | ร่วมโครงสร้างนโยบายเดิม เป็นผู้อนุมัติภารกิจสำรองเมื่อผู้รับผิดชอบกับเจ้าสำนักไม่พร้อม |
| ผู้คุมกฎสำนัก (`discipline`) | กฎ ข้อสงสัยบัญชี และการตรวจสอบในระบบวินัยเดิม; ไม่กล่าวโทษจากข่าวลือที่ยังไม่มีหลักฐาน |
| กิจการนอกสำนัก (`mission`) | อนุมัติ/เลือกแนวภารกิจจากกำลัง นโยบาย เส้นทาง ความกล้า ความระวัง ความต้องการทรัพยากร |
| แม่ทัพสำนัก (`commander`, ใหม่) | เข้าร่วมศึกบุกจริง เลือกแนวตั้งรับ/รุกตามความระวังและเห็นใจ ภาวะผู้นำช่วยระดมกำลัง; ตั้งรับลดโอกาสส่งผู้บาดเจ็บเข้ารบ |
| หัวหน้าองครักษ์ | เฝ้าประตูและช่วยระดมกำลัง รับช่วงนำศึกได้หากแม่ทัพไม่พร้อม |
| หอยุทธ์ | ฝึกและเตรียมพร้อมต่อสู้ เป็นผู้นำศึกสำรองถัดไป |
| หอโอสถ | เลือกใบสั่งผลิตจริงตามของขาด ต้นทุนและบุคลิก เช่น ความเห็นใจเพิ่มความสำคัญของยารักษา |
| โรงหลอม | เลือกใบสั่งผลิตจริงตามอุปกรณ์และทรัพยากรที่ต้องการ |
| หอคัมภีร์ | ดูแลงานเรียน/ชี้แนะตามระบบเดิมและเป้าหมายวิชาของเจ้าตัว |
| หอคลัง | เงิน ของสำรอง และของขาด; ระบบสวัสดิการ ตลาดภายนอก และการเอนเอียงตามสายสัมพันธ์เดิมยังทำงาน |
| หอทะเบียน | พิจารณาสมาชิกตามความสามารถ/นโยบายและบุคลิกในระบบรับศิษย์เดิม |
| หมอหลวง | ประเมินความจำเป็นของผู้บาดเจ็บและกิจกรรมสถานรักษา |
| ฝ่ายเสบียง (`provision`, ใหม่) | อ่านอาหารพร้อมกิน/ข้าวสาร ออกข้อเสนอให้ทำอาหารหรือเพาะปลูกตามของที่มี |
| ฝ่ายสมุนไพร (`herbal`, ใหม่) | อ่าน material shortage ที่เป็นสมุนไพรจริง ประสานเก็บ/ปลูก |
| ฝ่ายลาดตระเวนอสูร (`wildwarden`, ใหม่) | ประเมินอสูรในแผนที่/อสูรตำนาน แจ้งเตือนและปรับข้อเสนอเฝ้ายาม/ล่า |
| ฝ่ายอาคารสถานที่ (`steward`, ใหม่) | อ่านความแออัดของสถานี เสนออาคารที่ยังขยายได้ เจ้าสำนักยังเป็นผู้ตัดสินใจใช้งบ |

ข้อเสนอฝ่ายเพิ่มน้ำหนักการตัดสินใจของสมาชิกอย่างจำกัด สมาชิกยังมีความชอบ/ข้อจำกัดของตน ไม่ใช่คำสั่งควบคุมทุกคน ตารางรวมหน้าที่เดิมและส่วนที่เพิ่ม ไม่ได้หมายความว่าทุกฝ่ายมีระบบบริหารใหม่ทั้งชุด

แม่ทัพเปิดให้แต่งตั้งเมื่อมีสมาชิกที่ยังอยู่ในสำนักอย่างน้อย 12 คน อีกสี่ฝ่ายใหม่เมื่อมีอย่างน้อย 16 คน เจ้าสำนักยังต้องหาผู้มีคุณสมบัติและไม่มีตำแหน่งอื่นก่อน ไม่แต่งตั้งอัตโนมัติทันทีที่ครบจำนวน แม่ทัพที่หนี/ยอมแพ้/บาดเจ็บหนักเสียสถานะผู้นำ มีการพิจารณาคนสำรองในศึกเดิมและรักษาเพดาน 14 ผู้ป้องกัน

## ตำแหน่งอนาคตและ UI

ไปที่ **สำนัก → ตำแหน่ง** จะเห็นตำแหน่งที่ว่างแยกจาก **🔒 ยังไม่ปลดล็อก** พร้อมเหตุผล ตำแหน่งที่เตรียมไว้คือ การทูตเฉพาะฝ่าย, ข่าวกรอง, สัตว์วิญญาณ, ค่ายกลประจำพื้นที่, ศิษย์สืบทอด/หลักสูตรรายฝ่าย

`SECT.PLANNED_POSTS` เป็นแค็ตตาล็อกสำหรับ UI ไม่อยู่ใน `POST_IDS` และไม่ใช้กำลังคน/เงินเดือน/สิทธิ์ราชการ เรียก `SECT.appoint` กับตำแหน่งนี้ก็ไม่ได้ การเปิดใช้ในแพตช์อนาคตต้องทำระบบจริงก่อน เพิ่มตำแหน่งนั้นใน `POSTS` พร้อม hall/หน้าที่ใน cognition/เกณฑ์ความเหมาะสม/ทดสอบ แล้ว UI จะเลิกแสดงเป็นรายการล็อกเอง อย่าเปิดด้วยเวลาจำลองหรือแฟล็กที่ไม่มีระบบรองรับ

หน้า NPC → ภาพรวม เพิ่ม “หน้าที่และความตั้งใจ” แสดงบทบาท เป้าหมาย และการพิจารณางานล่าสุด ข้อความเป็นการพิจารณา ไม่อ้างว่าโครงการสำเร็จแล้ว

## โครงสร้างและขอบเขตสำหรับ AI รับช่วง

- `n.cognition`: JSON version 1, goal หนึ่งรายการ, memory สูงสุด 24, trace สูงสุด 8, office snapshot, officeDecision และ nextReview; รองรับการบันทึก/โหลดตามระบบเดิม
- `COG.prepare` เลือก/ทบทวนเป้าหมายด้วย `W.rng` เท่านั้น ส่วน `role` / `modifiers` / `explain` ไม่กิน RNG และไม่เพิ่มสถานะ การเปิดแผ่นข้อมูลซ้ำไม่เปลี่ยนการจำลอง
- `COG.chosen` บันทึกเหตุผลของกิจกรรมที่เริ่มจริง และ wildlife ส่ง outcome ผ่าน `COG.remember`; อย่าใช้ RNG ใน comparator หรือ UI
- `sect.officePlans` มีได้ตามตำแหน่งที่เปิดใช้ มีวันหมดอายุและผู้รับผิดชอบ ไม่สะสมประวัติไม่จำกัด
- ตัวเลือก/การเดินทาง/การผลิต/ค่าธรรมเนียม/สวัสดิการ/ตลาด/การต่อสู้ยังผ่านระบบเดิม ไม่จำลองของหรือแต้มอีกรอบ
- `AI.ACTS` ใช้ชื่อจริง `shop`, `paidTraining`, `pray` เป็นต้น มี regression ป้องกันการใช้ชื่อสมมติที่ไม่มีใน runtime

ยังไม่ทำระบบข่าวลือสามฝ่าย, แค้นจนบุกล้างแค้นอัตโนมัติ, ช่วยเพื่อนในศึกแบบเต็ม, เป้าหมายเลี้ยงศิษย์หลายขั้น, คะแนนบุญคุณในการเลือกเจ้าสำนัก หรือขบวนล่าอสูรตำนานที่แม่ทัพจัดเอง ส่วนนี้ต้องเพิ่มการรับรู้ ข่าวสาร ความเสี่ยง และบัญชีผลลัพธ์ก่อนเพื่อไม่ให้อ้างเหตุการณ์เท็จ การล่าใช้ข้อมูลแผนที่ที่ระบบเดิมรู้และความจำเฉพาะตัว ยังไม่ใช่การรับรู้โลกแบบมีหมอกข้อมูลครบระบบ

อสูรบนแผนที่ยังไม่กลายเป็นผู้บุกสำนักเพียงเพราะมีแม่ทัพ แม่ทัพนำเหตุการณ์บุกที่มีอยู่จริงและพร้อมต่อยอดเหตุการณ์ในอนาคต

## บั๊กที่รวมมา

การเติมสัตว์ธรรมดาเคยสุ่ม Pool อสูรตำนานของโซนเหนือได้แม้ rare roll ไม่ผ่าน แยก ordinary/legendary eligibility และคุมเพดานอสูรตำนานหนึ่งตัวร่วมทุกโซนแล้ว การเกิดตำนานยังผ่าน rare roll เดิมและจากไปตามช่วงเวลาสุ่มเดิม

การตรวจระยะยาวมี assertion ประวัติการค้าสูงสุด 60 แต่ตัวบันทึกตลาดภายนอกจำกัด 80 อยู่แล้ว ปรับ assertion เป็น 80 ให้ตรงขอบเขตจริง โดยไม่ได้เพิ่มเพดาน runtime
