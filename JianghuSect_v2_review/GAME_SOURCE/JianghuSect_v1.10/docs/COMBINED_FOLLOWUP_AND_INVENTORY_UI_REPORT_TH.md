## 2. การออกแบบและสถาปัตยกรรม UI ตารางไอคอนแบบแบ่งหน้า (Inventory, Sect Storage & Shop UI)

### 2.1 โหมดการแสดงผลและการบันทึกค่าตั้งต้น
- ผู้เล่นสามารถสลับระหว่าง **ตารางไอคอนแบบแบ่งหน้า (`⊞ ตารางไอคอน` / `grid`)** และ **รายการแบบดั้งเดิม (`☰ รายการ` / `list`)** ได้ทันทีจากปุ่มสลับบนหัวข้อของทั้ง 3 หน้าจอ:
  1. **ถุงสัมภาระส่วนตัวของตัวละคร** (`UI.rNpc` แท็บภาพรวม และ `UI.rEdit` แท็บจัดการถุง/คลัง)
  2. **คลังสำนัก** (`UI.rSect` แท็บ `stock`)
  3. **ร้านค้าสำนักและกระดานคุณูปการ** (`UI.rSect` แท็บ `shop`)
- สามารถเปลี่ยนค่าเริ่มต้นได้ใน **เมนู -> ตั้งค่า (`#invViewModeSel`)** โดยบันทึกค่าลง `localStorage.getItem('jh_inv_view_mode')` และ `G.opts.invViewMode` อัตโนมัติ
- ทั้งสองโหมดเรียกใช้ฟังก์ชันข้อมูลและธุรกรรมชุดเดียวกัน (`UI.buildPersonalBagItems`, `UI.buildSectStockItems`, `UI.buildSectShopItems`, `SECT.EDITOR.*`, `CPE.buy`, `MARTIAL.startStudy`) การสลับโหมดจึงไม่เคยทำให้ไอเทมซ้ำ จำนวนเพี้ยน ราคาเปลี่ยน หรือกระทบการตัดสินใจของ NPC

### 2.2 การจัดวางตารางไอคอน การแบ่งหน้า และหมวดหมู่
- **จำนวนคอลัมน์ปรับตามขนาดหน้าจออัตโนมัติ**:
  - มือถือจอแคบ (`< 400px`): **5 คอลัมน์ × 3 แถว** (15 ช่อง/หน้า, ขนาดปุ่มสัมผัส ~56×56px)
  - มือถือมาตรฐาน (`400px–599px`): **6 คอลัมน์ × 3 แถว** (18 ช่อง/หน้า)
  - แท็บเล็ต/แนวนอน (`600px–959px`): **8 คอลัมน์ × 3 แถว** (24 ช่อง/หน้า)
  - เดสก์ท็อป (`>= 960px`, ขยายแผ่นข้อมูลเป็น `.wide-inv`): **10 คอลัมน์ × 3 แถว** (30 ช่อง/หน้า)
- **หมวดหมู่หลัก 6 หมวด (`BROAD_CATS`)**: `ALL` (ทั้งหมด), `PILL` (💊 โอสถ), `EQUIPMENT` (🗡️ อุปกรณ์), `MATERIAL` (🌿 วัตถุดิบ/อวัยวะอสูร), `MANUAL` (📜 คัมภีร์/ผลึก/ตำรับ), และ `OTHER` (🍚 เสบียง/ศิลา) พร้อมตัวเลขแสดงจำนวนในแต่ละหมวด
- **สัญลักษณ์บนช่องไอคอน (ไม่พึ่งสีเพียงอย่างเดียว)**:
  - มุมซ้ายบน: สัญลักษณ์ความหายาก + ระดับ (`★T7` ตำนาน, `◆T5` ล้ำเลิศ, `▲T3` หายาก, `T1` ทั่วไป)
  - มุมขวาบน: สถานะสำคัญ (`สวม` เมื่อสวมใส่อยู่, `🔒` เมื่อติดเงื่อนไข/แต้มไม่พอ, `ขาด`/`+ล้น` ในคลังสำนัก, หรือ `%` คุณภาพเมื่อไม่ใช่ 100%)
  - มุมซ้ายล่าง: ราคา `คป.` ในร้านค้า หรือป้าย `เสก` สำหรับไอเทมที่ผู้เล่นเสก
  - มุมขวาล่าง: จำนวนในกอง (`×N`)

### 2.3 แผงรายละเอียดแบบกะทัดรัด (Compact Detail Panel)
- แตะไอคอนใดจะเปิดแผงรายละเอียดด้านล่างตารางทันที (ไม่บังตารางไอคอนและไม่ต้องเลื่อนหา) หากแตะไอคอนอื่นจะเปลี่ยนข้อมูลในแผงเดิมทันทีโดยไม่ต้องกดปิดก่อน
- แสดงข้อมูลสำคัญครบถ้วน: ชื่อภาษาไทย, หมวดหมู่, ระดับ/ความหายาก, คุณภาพ, จำนวน, สรรพคุณจริง, ปุ่มปิด (`✕ ปิด`), ปุ่มคำสั่งที่อนุญาต (`สวมใส่`, `ถอดเก็บ`, `คืนคลัง`, `ใช้งาน`, `บริจาค`, `แลกซื้อ`, `ชำระค่าศึกษา`), และปุ่ม **`▼ รายละเอียดเพิ่มเติม`** สำหรับดูเงื่อนไข ขั้นตบะ ที่มา และมูลค่าประเมิน

  - **ช่อง `62..63` (2 ช่อง Fallback กรณีฉุกเฉิน)**: ช่อง `62` (`FALLBACK_UNKNOWN_LEGENDARY`) สำหรับไอเทมตำนานที่ไม่รู้จักในอนาคต และช่อง `63` (`FALLBACK_GENERIC`) สำหรับไอเทมทั่วไปที่ไม่รู้จัก (ปัจจุบันศาสตราตำนานทั้ง 11 ชิ้นและวิชาตำนานทั้ง 22 ชิ้นมีไอคอนเฉพาะครบ 100% ไม่มีรายการใดตกหล่นไปใช้ Fallback)

## 4. ความคิดริเริ่มและการปรับปรุงเพิ่มเติมที่เพิ่มให้เหนือกว่าโจทย์

1. **ตัวเลือกผู้ซื้อแบบโต้ตอบได้ในร้านค้าสำนัก (`#shopBuyerSel`)**: เดิมหน้าร้านค้าสำนักเป็นเพียงป้ายแสดงราคาให้ NPC เดินมาซื้อเอง เราได้เพิ่มตัวเลือกศิษย์ผู้ทำรายการพร้อมแสดงแต้มคุณูปการคงเหลือ และตรวจสอบเงื่อนไขขั้นตบะ/วิถี/สิทธิ์หอคัมภีร์แบบเรียลไทม์ พร้อมปุ่มแลกซื้อหรือชำระค่าศึกษาที่เรียกใช้ `CPE.buy` และ `MARTIAL.startStudy` เดียวกับที่ NPC ใช้จริง
2. **ความครบถ้วนของถุงสัมภาระส่วนตัว (`buildPersonalBagItems`)**: เพิ่มการแสดงผล `craftedPills` (โอสถที่ศิษย์ปรุงเองและเก็บไว้ในตัว) และ `subManuals` (คัมภีร์สายย่อยในถุง) ที่เดิมตกหล่นจากหน้ารวมถุงส่วนตัว
3. **แผงเลือกแนวทางคลี่คลายเบาะแสและพยากรณ์ความพร้อมใน `UI.rClueDetail`**: ให้ผู้เล่นสามารถดูโอกาสสำเร็จคาดการณ์จาก `VC.forecastNodeReadiness` และเลือกแนวทางรับมือด่านปัจจุบัน (`preferredApproach`) รวมถึงดูบันทึกการปะทะรายรอบและบันทึกเหตุผลที่สหายปฏิเสธคำชวนร่วมคณะ

## 5. ผลการทดสอบและข้อจำกัดที่เปิดเผยอย่างตรงไปตรงมา

- **การทดสอบ Regression และ Browser E2E**:
  - `node test/run_all.js`: **ผ่านครบ 63/63 กลุ่มทดสอบ** (รวม `codex_combined_review` และ `inventory_grid_ui_suite`)
  - การทดสอบออฟไลน์ (`file://` พร้อมบล็อกเครือข่ายภายนอก): ยืนยันว่า `JianghuSect_single.html` โหลดไอคอนจาก Embedded Atlas Data URI ได้ครบทุกช่องโดยไม่ต้องเชื่อมต่ออินเทอร์เน็ต
  - การทดสอบขนาดหน้าจอ (`360×800` แนวตั้ง, `800×360` แนวนอน, `412×860` มือถือมาตรฐาน, `1280×800` เดสก์ท็อป): ไม่มี Horizontal Overflow, ปุ่มไอคอนมีขนาดสัมผัส `>= 42–56px`, และแผงรายละเอียดไม่บังช่องไอคอน
- **การเปิดเผยข้อจำกัดด้านฮาร์ดแวร์**: การทดสอบหน้าจอมือถือและการสัมผัสทั้งหมดดำเนินการผ่าน **Headless Chromium Mobile Viewport & Touch Emulation (Playwright CDP)** บนสภาพแวดล้อม VM ไม่ได้ทดสอบบนเครื่องโทรศัพท์จริง (Physical Phone Hardware)
