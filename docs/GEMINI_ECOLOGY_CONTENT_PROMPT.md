# งานพัฒนาอิสระสำหรับ Gemini 3.8: Living Beast & Craft Expansion

## 0. คำสั่งและขอบเขต

คุณคือผู้ลงมือพัฒนาต่อจากแพตช์วิถี/วิชา/ผลึก/อุปกรณ์ ผู้ใช้ให้สิทธิ์ตัดสินใจและเพิ่มเติมความคิดสร้างสรรค์แล้ว เอกสารนี้เป็นคำสั่งให้ทำจริง ไม่ใช่คำขอให้ตอบแผน ลงมือ ทำให้ระบบเชื่อมกัน ทดสอบ แก้ข้อผิดพลาด อัปเดตเอกสาร commit และ push `main-1` เมื่อผ่าน ห้ามแก้/merge/force-push `main` ไม่ต้องรอผู้ใช้เขียนพรอมต์เพิ่ม

ขยายอสูร วัตถุดิบ และสูตรจำนวนมากอย่างมีเหตุผลทางนิเวศและเศรษฐกิจ ไม่ต้องเพิ่มวิถีหลักหรือรื้อสมดุลวิชาทั้งหมดในงานนี้ งานก่อนมีอุปกรณ์ชนิดชัดเจนและโบนัสตามสาย ให้ใช้ของเหล่านั้นเป็นฐาน

ถ้าเจอข้อกำหนดรองที่ทำไม่ได้ด้วยระบบจริง ให้เลือกวิธีที่เรียบง่ายและทำงานได้ บันทึกข้อแตกต่างพร้อมเหตุผล ห้ามเงียบตัดส่วนหลักแล้วอ้างเสร็จ ห้ามลด assertion หรือเสกของเพื่อให้เทสต์ผ่าน แยกผลทดสอบจริงกับสิ่งที่ยังไม่ทดสอบ

## 2. เป้าหมายเชิงปริมาณและคุณภาพ

เพิ่มอสูร80ชนิด วัตถุดิบอย่างน้อย160รายการ สูตรใหม่80สูตรพร้อมผลผลิตจริง ให้เริ่มตัวอย่างแนวตั้ง3ชนิดก่อน แล้วขยายเป็นชุดละ10–15ชนิดเมื่อการเชื่อมทำงาน จำนวนเป็นเป้าหมายของแพตช์นี้ ถ้าทำได้ไม่ครบให้รายงานเป็นงานที่ยังไม่เสร็จ ระบุจำนวนที่ทำได้และสิ่งที่เหลืออย่างชัดเจน ห้ามทำให้จำนวนลดลงเงียบๆแล้วใช้คำว่าเสร็จ ห้ามสร้าง placeholder เพื่อให้ครบ

อสูรแต่ละชนิดต้องมีถิ่นและพฤติกรรม/บทบาทนิเวศที่ต่างพอสมควร มีชิ้นส่วนเฉพาะอย่างน้อย2อย่าง อย่างน้อยหนึ่งอย่างเป็น input ในสูตรที่มีประโยชน์ อีกอย่างใช้ได้ในสูตรรอง/หลายสูตร หรือมีผู้ซื้อภายนอกและเหตุผลความต้องการที่ทำงานจริง วัตถุดิบห้ามเป็น dead content ที่ใช้หรือขายไม่ได้

ไม่บังคับให้อสูรทุกตัวหรือสูตรทุกสูตรแตกต่างด้วยกลไกใหม่ สายพันธุ์ใกล้กันแชร์ภาพ/พฤติกรรมได้ แต่ชื่อ สี ถิ่น ส่วนที่ได้ และบทบาทควรสอดคล้อง

ธาตุใช้ codeที่ระบบรู้จริง เช่น FIRE/WATER_ICE/WOOD_LIFE/EARTH_METAL/LIGHTNING/WIND/YIN_SHADOW/LIGHT_YANG/SOUL_DIVINE/ASTRAL ตรวจ catalog ก่อน อย่าประดิษฐ์ effect field แล้วถือว่ามีผลเอง

### tier กับกำลังรบ

ค่าตั้งต้นเพื่อเทียบของเดิม: tier1 cpประมาณ95, tier2 210, tier3 460, tier4 960–1120, tier5 2400–2680, tier6 6100–9200, tier7 14800–24500 ใช้เป็นช่วงอ้างอิง ไม่ใช่คัดลอกเท่ากันหมด ทำบทบาทคล่องตัว/เกราะ/ปราณโดยไม่ทำให้ tierต่ำมีพลังเท่าอีก3tier อย่าปรับสูตรหลักของ NPC เพียงเพื่ออสูรใหม่

ล่าหนึ่งตัวไม่ได้ของครบทุกชนิดใน drops: ใช้กฎดรอปจริงเดิมหรือขยายตัวเลือกแบบมีน้ำหนักและจำนวนจำกัด ถ้าจะเพิ่ม dropTable ต้องเขียน consumer + validation และรักษา drops:string[] เป็น compatibility projection สำหรับระบบที่ยังอ่านอยู่ ห้ามเพิ่ม object ลง drops ที่ codeคาดว่าเป็น ID

## 4. ถิ่น Pool และการเกิด

แผนที่สำนักมี meadow/ridge ทางใต้ west_grove ตะวันตก east_crag ตะวันออก north_peak ทางเหนือ และ legend; ตรวจ WILD.zones จริงก่อนใช้ ระดับแต่ละทิศต่างกันได้ ไม่ต้องทำรอบกำแพงระดับต่ำหมด

แต่ละโซนมีหลาย pool เช่นฝูงสัตว์ ดงพิษ ลำธาร และช่องเขา แต่ละ pool รวมtierติดกันประมาณ1–2ระดับ ไม่จับtier1กับtier5ในpoolเดียวเพียงเพราะสีเหมือนกัน อาจปรับpoolเดิมหรือเพิ่มpoolใหม่ที่มีเส้นทางเข้าถึงได้ รักษากำแพงและขอบแมพ ไม่วางสัตว์ในอาคาร/ช่องเดินที่เข้าไม่ได้

- ยึด peaceful/ไม่โจมตีก่อนใกล้พื้นที่ปลอดภัยตามเดิม; อสูรบนแผนที่ไม่บุกสำนักเอง
- ใช้ WILD.spawn(W,zoneId,poolId,opts) ตาม implementationจริง รักษา ordinary/legendary eligibility และ global active legendary cap1
- tier6/7บนแผนที่ต้องมีpoolที่legendary:trueหรืออยู่ในlegendary zone และ tier/speciesIdsรองรับจริง เพราะ rare spawnเลือกเฉพาะpoolที่ผ่านกฎนี้ แค่ใส่IDในpoolธรรมดาไม่ได้ทำให้เข้าถึงได้ ทั้งนี้ตำนานภารกิจไม่จำเป็นต้องเป็นแผนที่ทุกตัว ให้ระบุแหล่งอย่างตรงไปตรงมา
- อสูรตำนานมีอายุสุ่ม a–b ตามเดิม แจ้งปรากฏ/จากไป ไม่บอกเวลาถอยแน่นอนแก่ผู้เล่น ไม่มีตัวค้างตลอด
- ไม่เพิ่มจำนวนอสูร active พร้อมกันเป็น80ตัวเพียงเพราะ catalogมี80 รักษา capเดิมและประสิทธิภาพ
- ภารกิจบุก X.spawnRaid เดิมเลือก speciesที่ !sourcePack และ tierถึงเกณฑ์: อสูรน้ำ/พฤกษาที่เดินบุกบนบกไม่ได้ต้องมี eligibilityจริง เช่นcanRaidLandที่ consumerอ่าน ห้ามทำให้ปลาหรือสัตว์น้ำลอยเข้าประตูสำนัก และอย่าใส่sourcePackเทียมเพื่อซ่อนปัญหา
- ชนิด AQUATIC ถ้าแมพยังไม่มีน้ำ/การเข้าถึงที่เหมาะ ให้ใช้ภารกิจพื้นที่น้ำ/ริมฝั่งจริง ห้ามวางปลาลอยบนลานแห้ง
- เชื่อมบางชนิดเข้าภารกิจและถ้ำตามภูมิประเทศและระดับด้วย อย่าเพิ่มเฉพาะ species แล้วไม่มีpoolใช้
- ถ้า sourcePack ทำให้ชนิดถูกกรองออกจากระบบเดิม ให้ตัดสินใจชัดว่าจะลงระบบใด และทดสอบว่าเข้าถึงได้จริง ไม่เปลี่ยนฟิลด์สุ่มเพื่อข้ามข้อจำกัด

`family/archetype/visual/tags/sourceBeastIds` รวมถึง `beast.element` เป็น metadataใหม่ที่คุณต้องเพิ่ม consumer/validator หากจะใช้งาน ไม่ใช่ APIเดิมที่ยืนยันว่ามีแล้ว elementอาจเป็นแค่สี/ธีมจนกว่าจะเชื่อมผลต่อสู้จริง ห้ามอ้างว่ามีดาเมจ/ต้านธาตุจากmetadataอย่างเดียว `BEAST_PART` ต้องตรวจหมวดเดิมและ matcher ราคา/การเก็บก่อน: หาก nativeใช้ codeอื่น ให้ใช้ codeนั้นหรือเพิ่มการรองรับให้ครบ อย่าอาศัยตัวอย่างเป็นข้ออ้างไม่อ่านโค้ด

## 6. แผนสูตร80สูตรที่ต้องมีประโยชน์

แนะนำ48สูตรโอสถ +32สูตรอุปกรณ์ ตัวเลขปรับย่อยได้ถ้ายังครบ80และทุกสูตรมีผู้ใช้จริง:
- โอสถ:16ฟื้นฟู/ถอนพิษ/พักผ่อน,16บัฟต่อสู้มีเวลาจำกัดและต้นทุน,16ช่วยบำเพ็ญ/งานผลิตที่ engineรองรับจริง กระจายสูตรtier1–6 โดยวัตถุดิบจากอสูรtier7ใช้กับสูตรปลายเกมtier6ได้ อย่าทำบัฟถาวรเสกสเตตัสไม่จำกัด
- อุปกรณ์:14ประเภทใน MARTIAL.TYPES ได้แก่ SWORD/BLADE/BOW/SPEAR/STAFF/FIST/FOCUS, HEAVY/LIGHT/ROBE, RING/NECKLACE/BRACELET/CHARM รวม32ชิ้น เติมช่วงและบทบาทที่ของเดิมขาด ไม่เพิ่มslot ลำตัวใส่ได้ชิ้นเดียว เครื่องประดับคงจำนวนslotเดิม
- แต่ละสูตรใช้ชิ้นส่วนใหม่ร่วมกับสมุนไพร/แร่/วัตถุดิบเดิมที่มีแหล่งจริง ส่วนผสม2–4ชนิดเป็นค่าเริ่มต้น หลีกเลี่ยงวัตถุดิบหายากtier7เป็นinputบังคับของยาประจำวันtier1
- ทุกmaterialต้องมีปลายทางใช้หรือผู้ซื้อจริง ถ้ามี160partsและ80recipes เฉลี่ยสูตรละ2partsช่วยเชื่อมครบ ใช้cross-familyตามเหตุผล เช่น เกราะหนังใช้หนัง+เอ็น; ยาใช้ต่อม/แก่น+สมุนไพร ไม่ใช้หนังสร้างโอสถทุกสูตรโดยไม่มีคำอธิบาย
- ผลผลิตtierต่ำยังมีคุณค่าเพราะความต้องการประจำวัน คุณภาพขึ้นกับฝีมือผ่าน ECOเดิม งานผลิตใช้สถานีและจำนวนผู้ใช้จริง ไม่เปิดหลอมทุกที่
- ตรวจ cost จาก ECO.inputCost/outputValue และราคาCP/ภายนอกจริง ไม่กำหนดขายสูงมากจนฟาร์มสร้างกำไรไม่จำกัด อย่าเติมราคาในfieldที่ consumerไม่อ่าน
- สูตรบางส่วนเปิดตาม recipeTierได้ บางส่วน discoverableผ่านระบบม้วนตำรับที่มีอยู่ หาก discoverableให้มีแหล่งพบจริงและการขอสิทธิ์ศึกษา อย่าทำทุกสูตรlockedแล้วไม่มีใครค้นพบ

ข้อจำกัดrecipeTier: ระบบวิจัยเดิมเปิดถึง6 และ ECO.recipeKnown/recipeKnownForบล็อกสูตรtier7 แม้ถือม้วนตำรับเอง งานนี้ให้สูตรใหม่tier1–6 ไม่ทำสูตรtier7ที่เข้าถึงไม่ได้ และไม่แก้เซฟเพื่อปลดล็อก หากจะขยายresearch7ต้องเสนอเป็นกลไกแยกพร้อมต้นทุนและtests ไม่ถือว่าเป็นแค่เติมdata

ผล effect ใช้ keyที่ ECO.applyPill/CPEอ่านจริง ตรวจตัวอย่างจากสูตรที่ทำงานได้ บัฟสำรอง/ยารักษาชนิดใหม่ต้องถูก AI เลือกซื้อและใช้ได้จริง โดยเฉพาะ ST.preFight ใน stats.js เดิมรับเฉพาะkey P:CB_ ขณะที่ CPE.pickPurchaseข้าม cbBuff: ถ้าเพิ่มยาECO2_ต้องเปลี่ยนconsumerให้พิจารณาตาม effect/eligibility ที่เหมาะสมและมีNPCซื้อเตรียมศึกจริง ไม่เพียงเพิ่มfield cbBuffหรือเปลี่ยนprefixเพื่อหลอกเงื่อนไข ระบบเก่าบางจุดมี allowlist ของ BASIC_HP/BASIC_HP2 อย่าให้ยารักษาใหม่ค้างในกระเป๋าเพราะไม่เพิ่ม consumer ต้องแยกยาแรง/เงื่อนไขอย่างมีเหตุผล ไม่ทำให้ทุกคนกินทุกเม็ด

เมื่อสูตร/อุปกรณ์ใหม่อ้างความชำนาญ ใช้ M.SKILL_IDS/M.SKILL_GROUPS และAPIอ่าน/ฝึกใน proficiency.js ที่มีอยู่จริง ตรวจชื่อpublicfunctionsจากไฟล์ก่อนเรียก ห้ามเพิ่มfieldทักษะแล้วอ้างว่าให้ผลโดยไม่มีconsumer ห้ามใส่BOW/STAFF/FOCUSใน HC.SKILL_IDS ที่ล็อก

รักษากฎretraining.js: เปลี่ยนวิถีเริ่มstage1/prog0 เปลี่ยนสายเดิมลดครึ่งปัดลงเสียอย่างน้อย2ขั้นและต่ำสุด1 มีแหล่งความรู้/ต้นทุน/การตัดสินใจหลายปัจจัย อุปกรณ์ดรอปใหม่ไม่สั่งNPCสลับสายทันที

ห้ามเพิ่มคัมภีร์/ผลึกเป็น guaranteed loot ของสัตว์ใหม่หรือสูตรผลิตความรู้ ใช้ shared discovery gate ใน knowledge.js เท่านั้นถ้าต้องเชื่อมความรู้ ไม่แปลงคัมภีร์ถาวรเป็นผลึกแจกได้ไม่จำกัด

## 8. NPC และเศรษฐกิจต้องครบวงจร

วงจรเป้าหมาย: ล่าอย่างเหมาะกำลัง → ได้ชิ้นส่วนจริง → เจ้าของเลือกเก็บ/บริจาค → คลังมีของ → เจ้าหน้าที่เลือกใบสั่ง/ซื้อของขาด → ผลิตที่อาคาร → สมาชิกใช้หรือซื้อ → ส่วนเกินขายคนนอกเป็นหินวิญญาณ → ซื้อของที่สำนักต้องการ

ข้อจำกัดตลาดเดิมที่ต้องอ่านก่อนอ้างขายได้: EXT.isTradableปฏิเสธmaterialtier>3 และpillที่ไม่ใช่basic การตั้งvalueอย่างเดียวจึงไม่ทำให้ของใหม่ถูกซื้อ/ขาย ถ้าจะให้ของเหล่านี้ผ่านตลาด ให้เพิ่มรายการ/เงื่อนไขพ่อค้าเฉพาะระดับอย่างมี stock/wants/wallet/cap จริงและtests ไม่เปิดขายtier7ทั่วไปหมดทุกวัน และถ้าเลือกไม่ให้ขายต้องมีปลายทางสูตรใช้ได้จริงให้ครบ

ใช้ระบบเดิมสำหรับCP scarcity/reward, CPE shop, EXTตลาดนอก, privatecraft, welfare/shortage directives ไม่เขียนวงจรเสกของคู่ขนาน NPCพิจารณานิสัย เป้าหมาย วิถี สายย่อย และweapon fit ไม่บังคับทุกคนเลือกของแพงที่สุดหรือบริจาคทุกอย่าง เพิ่มแหล่งซื้อ/ขายเฉพาะเมื่อมีสินค้าคงเหลือและเงินของอีกฝ่ายจริง

ห้ามขายทุกวัตถุดิบออกจนพรุ่งนี้ผลิตยาจำเป็นไม่ได้ ต้องเคารพ reserve/shortage และการเลือกเก็บของส่วนตัวของNPC ยาที่แจกใช้ stockจริงและแรงงานจริง ค่าผลิตคุณภาพสูงไม่ควรปั๊มแต้มจากของที่ไม่มีผู้ต้องการได้ไม่จำกัด

## 9. ขั้นตอนทำงานแบบกันพลาดสำหรับโมเดลขนาดเล็ก

A. สรุปทะเบียนเดิมและทำ manifestใหม่ กำหนดID prefixเดียว ห้ามชน ดูตัวอย่างจริงแล้วทำ validator ก่อนเพิ่มจำนวนมาก

C. ขยายทีละ10–15ชนิด ตรวจvalidatorทุกชุด อย่าให้ generated variationแทนความคิดสร้างสรรค์ทั้งหมด แต่ใช้generatorตรวจ/ประกอบfieldซ้ำได้และเก็บseedแน่นอน

Browserต้องมีPlaywright/Chromium ถ้าenvironmentไม่มีให้ใช้setupของenvironmentจริง อย่าเปลี่ยนเทสต์เป็นผ่านอัตโนมัติ ห้ามลงผลว่าทดสอบบนมือถือจริงถ้าใช้เพียงviewportจำลอง รันperfแยกจากlongrun ห้ามรันCPUหนักพร้อมกันแล้วสรุปว่าเกมช้า

ตรวจlongrun stock/CPไม่ติดลบ ข้อมูลไม่บวม มีผลิต/ซื้อ/ใช้/ขายจริง อสูรหลากหลายและความรู้ยังหายาก ไม่ต้องบังคับให้360วันพบตำนานหรือคัมภีร์เสมอเพราะเป็นเหตุการณ์หายาก แสดงจำนวนobservedและใช้forced testsยืนยันrarebranchesแทนการเพิ่มโอกาสเพื่อแต่งรายงาน

## 11. เอกสารและการส่งมอบ

- สร้าง JianghuSect_v1.10/docs/ECOLOGY_EXPANSION.md และmanifest machine-readableของชุดใหม่ พร้อมcounts/categories/แผนเชื่อม/drop rulesและข้อจำกัด
- READMEผู้เล่นบอกสิ่งที่เพิ่มและทางเข้าหน้าUI HANDOFFสำหรับAIระบุไฟล์/ชื่อAPI/schemaที่เพิ่ม/เหตุผล/เทสต์ที่รัน/ผลจริง ไม่เขียนว่าAPIมีถ้ายังไม่ได้สร้าง
- บันทึกค่าที่ปรับสมดุลและหลักฐานก่อน/หลังพอให้คนอื่นประเมิน ไม่ต้องเขียนประวัติลองผิดลองถูกยาว
- ก่อนpush: git diff --check, ตรวจไม่มีsaveผู้เล่น/token/credentials/node_modules/archiveซ้อนในrepo ไม่มีHC byteเปลี่ยน commitข้อความอธิบายพฤติกรรม แล้วpushเฉพาะmain-1 (ไม่force) ตรวจremoteheadตรงcommit
- ถ้าคนอื่นpushพร้อมกัน fetchและintegrateอย่างระวัง ห้ามทับงานผู้อื่น หากมีข้อขัดแย้งสำคัญบันทึกจุดและไม่กล่าวอ้างว่าpublishสำเร็จจนตรวจได้
- คำตอบสุดท้ายสั้น: commit/branch, จำนวนจริง, ระบบที่เชื่อมครบ, ผลtests/360วัน, ข้อจำกัดที่เหลือพร้อมลิงก์docs
