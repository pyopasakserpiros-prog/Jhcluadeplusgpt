# จุดส่งต่อ Jianghu 2.08

ฐานพัฒนาและรายละเอียดระบบ 2.07 อยู่ใน `V207_HANDOFF_TH.md` กติกาทั้งหมดในไฟล์นั้นยังใช้ ยกเว้นเลขรุ่น/ชื่อผลตรวจและรายละเอียดที่แก้ในแพตช์นี้

## จุดเปลี่ยนที่ต้องรักษา

- `sect-contributions.acquire(g,n,kind,id,mode,authorityNpcId,quantity)`: จำนวนทางเลือกต้องผ่านไปทั้ง preflight และ requisition ก่อนจ่ายเงินจริง เส้นทาง `takeIngredient` ส่งจำนวนที่ขาดในสูตร ไม่ใช้ค่าเริ่มต้น 2 หน่วย
- `craftForSect`: สำเนา `r.effect` มาก่อนฟิลด์มาตรฐานของพัสดุ เพื่อไม่ทำ craftBonus/escortSafetyBonus หาย และยังให้เจ้าของ/รหัส/ระดับ/ที่มาออกจากธุรกรรมจริง
- `grantEligibility`: ใช้ชื่อฤทธิ์หลัง normalize และต้องไม่มีฤทธิ์เพิ่มความก้าวหน้าแฝง แม้มีฤทธิ์รักษาอยู่ด้วย
- รายการงานผลิตและ UI รวม knownRecipes ของสมาชิกจริง ไม่จำกัดเฉพาะชุดสูตรเก่า และไม่แจกสูตรที่ยังไม่เรียน
- `economicWorkload`: ตัวนับและเพดานงานส่วนกลาง ใช้คนมีชีวิตกับงานในฉากที่กำลังเดิน/ทำจริง ทั้ง options และ infrastructure ต้องใช้ข้อมูลชุดนี้
- `sect-infrastructure.needs`: อัปเกรดอัตโนมัติเพื่อลดแรงกดดันต้องเพิ่มโบนัสที่ใช้ได้จริงจากอาคารระดับสูงสุด และหอภารกิจต้องพบช่องงานเต็มร่วมกับผู้ขาดแต้ม การสั่งอัปเกรดด้วยผู้เล่นยังทำได้ตามสิทธิ์/ต้นทุนเดิม
- `human.js` และ `legacy.bundle.js` ยังต้องคง bytes เดิม ไม่เพิ่มตัวตนคู่ขนาน และไม่ต้องรองรับเซฟแพตช์ก่อน

## คำสั่งตรวจและประกอบ

1. `npm test` รัน `tests/run_v208.cjs` ทั้ง 43 กลุ่ม รวม regression ใหม่และชุดจำลอง/เควสเดิม
